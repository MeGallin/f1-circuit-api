## Root cause and repair

Parent Render evidence at 10:20:24Z directly shows 2026/R19 publication failing
because a normalized Standing lacked required `podiums`. The lost GitHub run
41425940028 exception is not independently recovered from that evidence.

The normalizer already emits `podiums: null`; this and the required contract both
exist before 13 October (`ea73219`). Git blame attributes the faulty preservation
branch to `734a4ed` on 6 October. It returned the previous value for incoming
null/undefined even when no previous value existed, turning explicit null into
undefined. Standing IDs include the round; across rounds, positional fallback
worked only for equal-sized collections. A collection-size change exposed missing
prior values. The old live driver set had 23 rows; recovered R19 has 24.

The fix returns incoming null/undefined only when the prior value is undefined;
otherwise it retains the prior value. Prior null plus absent incoming stays null;
known enrichment and genuine zero/false retain their semantics. No invented counts
or zero values, ingestion-time derived calculations or relaxed schemas. Read
services still derive podiums, gaps and outlook. This is a latent preservation
defect, not evidence that the 13 October feature newly required podiums.

Schema failures now use `NORMALIZED_SCHEMA_INVALID`. The one-shot runner emits
sanitized structured code/message/year/round and independently attempts scheduler
stop and pool close; secondary errors do not replace primary diagnostics.
`sync_runs.error_code` retains stable valid root codes using its existing column.
Provider errors have stable HTTP/transport/timeout/JSON/schema/pagination/size/retry
classes and safe adapter-relative endpoint context. Optional weekend failures
retain diagnostic details without becoming fatal. Messages redact URLs,
credential assignments, auth tokens and PEM blocks, remove controls and are capped
at 500 characters. Output selects fields explicitly, excluding stack/body data.
